## 整体判断

视觉身份是明确的：暖色、克制阴影和桌游语义让页面不像通用文档模板。当前最大问题不是颜色，而是交互模型同时服务“第一次学习”和“桌边查规则”两种任务，导致两边都不够顺手。页面需要一个更明确的查阅路径，而不是继续增加更多折叠或 Tab。

## 检测器与浏览器证据

- CLI detector 对 `RulesGuideExperience.tsx` 报告 2 条 `gray-on-color`，位于决策选项的 `text-stone-700/text-stone-600` 与 `bg-amber-50` 组合。它们大概率是保守误报，但应复核实际对比度。
- 浏览器检测得到 23 个选择器组、27 个实例：15 条小字号提示、5 条低对比度提示、2 条图片裁剪提示、4 条图片 hover 缩放建议、1 条暗色发光提示。
- 小字号主要是 Tab 序号和相关游戏标签，序号可以保留，但功能性文字不应低于可读阈值。
- 图片裁剪和轻微缩放属于灯箱交互的合理实现；暗色发光是检测器注入层造成的误报。
- 浏览器脚本注入成功，但截图在 viewport 为 0×0 和后续截图超时后失败，因此没有可靠的用户可见覆盖层。

## 做得好的地方

1. 首屏先给游戏概述、目标和胜利条件，第一次打开就能建立心智模型。
2. 步骤、阶段和决策模块有明确的状态反馈，键盘 Tab 行为、焦点环和 reduced-motion 处理比较扎实。
3. URL hash、导出和图片灯箱对桌边查阅很有价值，整体暖色视觉也保持了 Game Shelf 的品牌连续性。

## 优先问题

### [P1] 缺少真正的“完整规则 / 查阅模式”

启用 JavaScript 后，完整 `rulesMd` 只在 `<noscript>` 回退中出现。需要 Ctrl+F、快速扫读或对照上下文的用户必须反复切换隐藏 Tab。

建议：增加“按步骤学习 / 完整规则”切换；完整模式用正常标题和可折叠细节呈现所有内容，并保留模块和条目的 hash 锚点。

### [P1] 移动端缺少页面级目录，桌面 Tab 也容易被裁切

`JumpNav` 当前只在 `lg` 以上显示；移动端只能沿长页面滚动，再横向寻找 Tab。七步准备在窄屏下尤其容易让用户不知道还有更多项目。

建议：移动端在规则头部增加可展开“本页内容”，并在 Tab 轨两端提供继续滚动的视觉提示；桌面可保留左侧阶段轨，步骤较多时也采用更稳定的纵向轨。

### [P1] 条目 hash 目前不能真正定位到页面元素

切换时写入 `#guide-setup--setup-terrain`，但页面没有同 ID 的元素，只有 `guide-item-setup-terrain` 和 `guide-panel-setup-terrain`。分享深链可以选择状态，却不会可靠地滚动到对应内容，也不会在 hash 变化后重新同步。

建议：让 hash 对应真实的 panel/heading ID，并在加载和 `hashchange` 时执行一次“选择条目 + 滚动 + 聚焦”；继续使用 `replaceState`，避免污染历史记录。

### [P2] 参考资料的 Tab 数量会反过来制造记忆负担

领国者的 `table-reference` 有 15 个同级项目，适合做分组索引而不是一条横向 Tab 轨；卡坦的单项目“快速查表”和单项目 FAQ 也不需要 Tab 外壳。

建议：单项目直接渲染内容；多项目按“组件 / 经济 / 判定 / 表格 / 官方裁定”分组，再用二级索引或搜索定位具体表格。

### [P2] 准备流程缺少桌面上的空间提示与完成感

“拼出海洋框架、放置地形、放置数字标记”对新玩家是空间任务，目前主要是文字。用户还需要自己判断是否已经完成全部准备。

建议：为准备模块增加一张简洁的版图标注图或 2–3 张关键状态图；在最后一步显示“准备完成，进入回合流程”的明确收束，并提供跳转。

## 用户画像风险

- **第一次玩家**：会问“桌面现在应该长什么样”和“我是否准备完了”；文字准确但缺少空间参照和完成反馈。
- **桌边查规则玩家**：希望扫读、搜索、对照上下文；隐藏内容、无完整模式和不可靠深链会增加切换成本。
- **移动端用户**：没有页面目录，只能滚动和横向拖动 Tab；长卡片留白和固定浮层会挤占拇指操作空间。

## 次要观察

- 中文页仍显示英文标签 `trading`、`engine-building`。
- 桌面目录没有当前模块高亮。
- 阶段模块的方向键切换后没有像通用 Tab 模块一样把焦点移到新 Tab。
- `labels.missing` 已定义但没有在缺失内容时显示。
- 图片 alt、按钮 aria-label 和可见标题可能造成重复播报。
- 检测器报告的 `#c4952a` 白底对比度 2.7:1、`#79716b` 浅底对比度 4.4:1，建议优先复核功能性文本而非边框装饰。

## 值得确认的问题

- 我们首要优化的是“第一次学会”，还是“游戏中快速查规则”？
- 完整规则是否应该成为启用 JavaScript 后仍可直接阅读的第一等入口？
- 对领国者这类长表格，分组索引是否比 15 个同级 Tab 更符合查阅习惯？
- 一张标注版图是否比继续增加导航控件更能降低新手准备成本？
